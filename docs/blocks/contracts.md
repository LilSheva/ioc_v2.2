# Нюансы реализации: Контракты (Ports Package)

Этот документ описывает абстрактные интерфейсы (Порты), расположенные в директории [ioc_analyzer/ports/](file:///d:/Рабочая Папка/ioc_parser_srv/1_project/ioc_analyzer/ports/), которые служат жестким контрактом взаимодействия между Ядром и внешними Адаптерами.

---

## 1. Назначение Портов в системе

Порты объявляются с использованием стандартного модуля Python `abc.ABC` (Abstract Base Classes) и декоратора `@abc.abstractmethod`.
* **Цель**: Определить сигнатуры методов ввода-вывода, скрывая за ними конкретные технологии. Ядро работает только с типами данных, описанными в порте, не зная, откуда они берутся (файл, сеть, почта Exchange или заглушка).
* **Преимущество**: Тестирование бизнес-логики ядра сводится к подмене адаптера на простой класс-мок (Mock), возвращающий заранее подготовленные тестовые структуры, без реального подключения к почтовым серверам или записи файлов.

---

## 2. Спецификация интерфейсов

### 2.1. DocumentPort ([document_port.py](file:///d:/Рабочая Папка/ioc_parser_srv/1_project/ioc_analyzer/ports/document_port.py))
Отвечает за чтение текстового содержимого бюллетеней и извлечение разметки.
* **Метод**: `extract_paragraphs(file_path: str) -> list[ParagraphData]`
* **Возвращаемая модель**: `ParagraphData` (dataclass в порте):
  - `text`: Строковое содержимое абзаца.
  - `has_top_border`: Логический флаг наличия верхней границы (линии).
  - `has_bottom_border`: Логический флаг наличия нижней границы.
* **Зачем нужны границы**: Для разметки блоков ГосСОПКА. Порт абстрагирует ядро от структуры XML-тегов `docx` (`w:pPr`, `w:pBdr`), приводя их к простым логическим флагам.

### 2.2. MailPort ([mail_port.py](file:///d:/Рабочая Папка/ioc_parser_srv/1_project/ioc_analyzer/ports/mail_port.py))
Отвечает за интеграцию с почтовым ящиком.
* **Методы**:
  - `fetch_unread_emails() -> list[EmailRecord]`: Возвращает список метаданных новых писем с вложениями, скачанными на диск.
  - `mark_as_read(mail_id: str) -> None`: Помечает сообщение как прочитанное на почтовом сервере.
* **Абстракция ID**: Почтовый идентификатор передается как простая строка `mail_id`. Внутри Exchange-адаптера он собирается как составная строка `"{item.id}:{item.changekey}"`, но ядро об этом не знает и работает с ним как с прозрачным идентификатором.

### 2.3. ExportPort ([export_port.py](file:///d:/Рабочая Папка/ioc_parser_srv/1_project/ioc_analyzer/ports/export_port.py))
Отвечает за создание каталогов и сохранение выходных отчетов.
* **Методы**:
  - `setup_directories(base_share_path: str) -> str`: Создает структуру папок на сетевом ресурсе (например, `2026-06-09_FSTEK-123/`) и возвращает путь к ней.
  - `export_report(report_data: ReportData, output_dir: str) -> str`: Сохраняет XLSX и CSV файлы и возвращает путь к основному XLSX-отчету.

### 2.4. IpBlockPort ([ip_block_port.py](file:///d:/Рабочая Папка/ioc_parser_srv/1_project/ioc_analyzer/ports/ip_block_port.py))
Отвечает за отправку IP-адресов на внешний **сайт блокировки** (отдельный HTTP API, не SIEM).
* **Метод**: `block_ips(ip_comments: dict[str, str]) -> tuple[bool, dict[str, dict[str, str]]]`
* **Конфигурация**: ключи `api_url` и `api_key` в `config.json` (заголовок `X-API-KEY`).
* **Заглушка**: `MockIpBlockAdapter` — no-op, если API не настроен.

### 2.5. SiemPort ([siem_port.py](file:///d:/Рабочая Папка/ioc_parser_srv/1_project/ioc_analyzer/ports/siem_port.py))
Зарезервирован для будущей интеграции с SIEM/NAD. Сейчас в рантайме не используется; есть `MockSiemAdapter` для тестов.
