# PURPOSE: Цели и задачи автоматизации обработки IOC

## 1. Контекст и проблематика (Боль аналитиков)
В процессе работы центра мониторинга информационной безопасности (SOC) дежурная смена регулярно получает бюллетени об угрозах от регуляторов (ФСТЭК России) и Национального координационного центра по компьютерным инцидентам (НКЦКИ / Госсопка). 
Эти бюллетени поступают в виде документов Microsoft Word (`.docx`) или электронных писем. 

**Ручной процесс обработки включает:**
1. Открытие каждого документа и поиск индикаторов компрометации (IP-адреса, домены, URL-адреса, хэш-суммы файлов, адреса электронной почты, пути реестра).
2. Извлечение этих данных с очисткой от маскирующих символов (например, замена `[.]` на `.`, `hxxps://` на `https://`).
3. Группировку индикаторов по типу действия: блокировка, поиск в логах или разблокировка.
4. Создание структуры каталогов для хранения исходных документов и извлеченных списков.
5. Формирование Excel-отчетов по установленному шаблону и текстовых файлов (фильтров) для сетевых средств защиты и SIEM-систем.

Этот процесс занимает значительное время дежурной смены, подвержен человеческим ошибкам (пропуск символов, опечатки) и задерживает скорость реагирования на угрозы.

---

## 2. Цели автоматизации
Проект **IOC-Analyzer** направлен на создание фонового сервиса (Daemon) и графического инструмента, которые полностью автоматизируют рутинные операции сбора, парсинга и экспорта индикаторов.

**Ключевые результаты:**
* **Сокращение времени реагирования** с 30-40 минут на один бюллетень до нескольких секунд.
* **Исключение человеческого фактора** при копировании сложных регулярных выражений и имен файлов.
* **Централизованное хранение** бюллетеней и результатов их парсинга на сетевом ресурсе.

---

## 3. Уровни интеграции системы

Система проектируется с учетом поэтапного расширения функциональности:

### Уровень 1: Автоматический сбор, парсинг и экспорт (Текущая стабильная база)
* Мониторинг почтового ящика дежурной смены (протокол EWS Exchange).
* Извлечение вложений `.docx` и перенос писем во временную директорию.
* Парсинг индикаторов компрометации с использованием специализированных режимов (ФСТЭК, Госсопка).
* Генерация структуры каталогов на сетевой шаре и экспорт результатов в Excel (`.xlsx`) и CSV-списки.

### Уровень 2: API-интеграция с SIEM (Внедрение)
* Автоматическая передача извлеченных индикаторов в SIEM-систему (например, MaxPatrol 10) через REST API для автоматического создания табличных списков и репутации IP/доменов.

### Уровень 3: Ретроспективный поиск (Перспектива)
* Автоматический запуск ретроспективных запросов в SIEM/NAD по историческим логам для обнаружения следов компрометации в сети за прошедшие 30-90 дней.
