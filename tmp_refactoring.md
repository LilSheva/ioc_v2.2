МОДУЛЬНАЯ ДОКУМЕНТАЦИЯ (Спецификации для ИИ-агентов)

1. docs/spec/PURPOSE.md (Суть проекта)
# PURPOSE: Автоматизация обработки IOC для дежурной смены

## Описание боли
Дежурная смена вручную обрабатывает бюллетени ФСТЭК и Госсопки. Требуется вручную извлекать IOC (IP, URI, хэши, email), заносить их в отчеты, формировать таблицы для SIEM и осуществлять блокировки.

## Цель автоматизации
Создать фоновую службу (Daemon), которая полностью убирает рутину ручного извлечения данных и подготовки фильтров для SIEM.

## Уровни интеграции
*   **Уровень 1 (Текущий приоритет):** Автоматический сбор писем с вложениями -> Парсинг IOC -> Автосоздание структуры папок на сетевом диске -> Генерация xlsx-отчетов/фильтров и csv-табличных_списков.
*   **Уровень 2 (В разработке):** Заливка табличных списков по API в SIEM.
*   **Уровень 3 (В разработке):** Автоматические исторические запросы по IOC в SIEM/NAD через API.

2. docs/spec/INFRA.md (Архитектурные правила сборки)
# INFRA: Архитектура Портов и Адаптеров

## Архитектурные правила
1. Код в папке `core/` не должен импортировать ничего из папки `adapters/` [technical_regulation_ai_refactoring_2026.md, 2.4].
2. Логика взаимодействия строится через интерфейсы в `ports/`.
3. Точка сборки (`run_daemon.py`) инициализирует конкретные адаптеры и внедряет их в ядро (Dependency Injection).

## Пример внедрения для Уровня 1:
При запуске `run_daemon.py` мы собираем приложение:
- `watcher = MailAdapter(config)`
- `exporter = LocalFSExporterAdapter(config)`
- `core_engine = IOCParserEngine(watcher, exporter)`

## Перспектива интеграции в дипломный проект (8-9 месяцев)
*   **Двухцелевое использование:** Этот модуль парсинга (`core/parser/`) будет использоваться в двух независимых окружениях:
    1. Рабочая среда: Фоновая служба (Daemon), обрабатывающая почту.
    2. Дипломная среда: Интерактивный GUI-интерфейс на Streamlit/Flet.
*   **Требование к коду ядра:** Все функции в папке `core/` должны быть "чистыми" (stateless). Они должны принимать на вход сырые данные (строки, файлы) и возвращать структурированные объекты/словари. 
*   **Запрещено:** Внутри `core/` запрещено использовать прямое логирование в файлы, печать в консоль (`print`), обращение к глобальным переменным окружения или сетевым ресурсам. Вся внешняя активность должна идти строго через Порты (`ports/`).
