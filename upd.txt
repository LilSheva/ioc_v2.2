\# 📋 Техническое задание: Интеграция парсера IoC с API системы блокировок и безопасное хранение учетных данных

\## 1. Контекст проекта

Разрабатывается утилита на Python для дежурной смены информационной безопасности. Утилита извлекает индикаторы компрометации (IP-адреса) из \.docx\ отчетов и автоматически отправляет их по API в систему блокировок. 

Скрипт собирается в \.exe\ (PyInstaller) и размещается на общедоступной сетевой шаре. 

\*\*Текущая задача:\*\* Реализовать модуль отправки извлеченных IP-адресов в API и модуль безопасного чтения API-ключа из внешнего файла (защита от "любопытных глаз" на сетевой шаре).

\---

\## 2. Модуль безопасности (Чтение токена)

Так как утилита лежит на сетевой шаре, хардкодить API-ключ в коде или хранить его в открытом текстовом файле нельзя. 

Требуется реализовать чтение ключа из внешнего файла \token.key\, где ключ хранится в обфусцированном виде (XOR + Base64). 

\*\*Логика работы:\*\*

1\. В коде должна быть зашита константа (например: \SECRET_KEY = b"MySuperSecretPhrase_For_Duty_Shift"\).

2\. Утилита читает файл \token.key\ (лежит в той же директории).

3\. Утилита декодирует строку из Base64 и применяет операцию XOR с \SECRET_KEY\ для получения реального токена (например: \qwerty\).

4\. Если файла нет или он поврежден — скрипт корректно завершает работу с выводом ошибки в консоль.

\*(Использовать только встроенный модуль \base64\, без сторонних крипто-библиотек).\*

\---

\## 3. Спецификация API (Модуль отправки)

Утилита должна собрать все найденные валидные IP-адреса в массив и отправить их одним POST-запросом.

\*   \*\*URL (тестовый):\*\* \http://localhost:8099/api/ipaddress\

\*   \*\*Метод:\*\* \POST\

\*   \*\*Авторизация:\*\* Заголовок \X-API-KEY: <расшифрованный\_токен>\

\*   \*\*Библиотека:\*\* \requests\ (передача данных через параметр \json=\)

\*\*Формат запроса (Payload):\*\*

Массив словарей. Обязательные поля: \ip\ и \comment\.

Комментарий должен формироваться на основе имени исходного файла (например: \*"Бюллетень ФСТЭК 12/34"\*).

\\\json

\[ 

    {"ip": "1.82.133.133", "comment": "ФСТЭК 12/34 от 10.10.2023"},

    {"ip": "192.168.1.1", "comment": "ФСТЭК 12/34 от 10.10.2023"}

\]

\\\

\*\*Формат ответа сервера (Response):\*\*

Сервер возвращает массив объектов с результатами (HTTP 200).

\\\json

\[ 

    { "id": "192.168.1.1", "text": "192.168.1.1 входит в диапазон...", "status": "ERROR_DENY_NET" }, 

    { "id": "1.82.133.133", "text": "1.82.133.133", "status": "OK" } 

\]

\\\

\## 4. Требования к логике обработки и логированию

После получения ответа от API скрипт должен распарсить JSON и вывести читаемый лог в консоль.

Необходимо обрабатывать следующие значения поля \status\:

\*   \OK\ — Успешно добавлено (Выводить \\[+\] Успех: <ip>\).

\*   \ERROR_DUPLICATE\ — Уже есть в базе (Выводить серым/нейтральным \\[i\] Пропуск: <ip> уже в базе\).

\*   \ERROR_DENY_NET\ — Попытка блокировки внутренних сетей (Выводить как Warning \\[!\] Внимание: <ip> отклонен сервером (внутренняя сеть)\).

\*   \ERROR_FORMAT\ / \ERROR_PREFIX\ / \ERROR\ — Прочие ошибки (Выводить \\[-\] Ошибка для <ip>: <text>\).

\*\*Обработка исключений:\*\*

Запрос к API должен быть обернут в блок \try-except\. При недоступности сервера (ConnectionError) утилита не должна падать (traceback), а должна выводить понятное сообщение: \*"Ошибка: Сервер блокировок недоступен"\*.
