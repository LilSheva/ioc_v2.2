# IOC-Analyzer v2.3 (SOC Automation)

Фоновая служба и графический интерфейс для автоматического сбора, парсинга и экспорта индикаторов компрометации (IOC) из бюллетеней информационной безопасности (ФСТЭК России и ГосСОПКА/НКЦКИ).

Проект спроектирован на базе **Гексагональной архитектуры (Ports & Adapters)**, разделяющей чистое математическое ядро RegExp-парсинга и внешние интеграции ( Exchange Web Services, выгрузка Excel, пуш по REST API в SIEM). Соответствует академическим стандартам выпускных квалификационных работ.

## ⚡ Быстрый старт

### 1. Установка зависимостей
Установите библиотеки, перечисленные в `requirements.txt`:
```bash
pip install -r requirements.txt
```

### 2. Настройка почты и путей
Откройте файл `.data/config.json` и настройте параметры:
*   `network_share_path`: Путь к сетевой шаре или папке, куда будут складываться отчеты.
*   `ews_email`: Email адрес ящика Exchange.
*   `password_file`: Путь к файлу с паролем EWS (для тестового хоста). Значение `"-"` или пусто — пароль берётся из переменной окружения.
*   `password_env_var`: Имя переменной окружения с паролем (прод, по умолчанию `EWS_PASSWORD`).
*   `save_dir`: Временная директория для скачивания вложений.
*   `ews_server`, `ews_username`: Параметры подключения к Exchange (hostname без `https://`, порт можно в `ews_port` или `host:444`).
*   `ews_port`: Порт EWS (часто `443`, у вас может быть `444`).
*   `ews_verify_ssl`: `false` — не проверять корпоративный/самоподписанный сертификат (только внутренняя сеть).
*   `api_url`, `api_key`: URL и ключ **сайта блокировки IP** (POST, заголовок `X-API-KEY`). Оба поля обязательны для отправки из GUI и демона.

Перед запуском демона задайте пароль в переменную окружения:
```powershell
# Windows PowerShell
$env:EWS_PASSWORD="ВашПароль"
```

### 3. Запуск GUI интерфейса
Для ручного разбора документов дежурной сменой:
```bash
python run_gui.py
```

### 4. Запуск фонового демона
Для непрерывной автоматической обработки почты на сервере (production):
```bash
python run_daemon.py
```

Для рабочего хоста с Outlook и сертификатом (тестовый режим расшифровки S/MIME):
```bash
python run_daemon.py -tst
```

> Важно: режим `-tst` предназначен только для рабочей станции с Outlook/Windows Cert Store.  
> В production-режиме (без `-tst`) зашифрованные S/MIME письма логируются как ошибка и пропускаются.

### 5. Поведение GUI при формировании отчётов
- При добавлении файлов режим `ФСТЭК/ГосСОПКА` определяется автоматически (можно поменять вручную).
- По кнопке **«Сформировать отчёты»** выбирается родительская папка, после чего создаётся структура:
  - `Задача` — исходные документы
  - `Отчет` — XLSX отчёты
  - `Шаблоны IOC` — CSV шаблоны
- После завершения по кнопке подтверждения открывается корневая созданная папка.
