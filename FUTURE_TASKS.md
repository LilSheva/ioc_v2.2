# Задачи на будущее (Интеграция с SIEM/NAD и правила фильтрации)

Ниже перечислены задачи и требования, которые мы зафиксировали на будущее для этапов интеграции с системами SIEM/NAD. На данном этапе эти задачи **не реализуются**, а сохраняются для справки.

## 1. Логика обработки "[множество пробелов]"
- В некоторых именах файлов содержится маркер `[множество пробелов]` (например, `Scan_САО ВСК_Претензионное письмо_278 [множество пробелов].exe`).
- При интеграции с SIEM/NAD необходимо разработать логику, которая будет интерпретировать этот маркер не как литеральную строку, а как регулярное выражение, соответствующее произвольному количеству пробелов (`\s+`), для точного поиска в логах.

## 2. Исключения доменов для поиска в SIEM/NAD
- Существует ряд доменов, которые формально по умолчанию заблокированы на корпоративном фаерволе (например, `discordapp.com`, `telegram.org`), либо легитимных публичных ресурсов с большим объемом трафика (например, `github.com`).
- Необходимо составить отдельный конфигурационный список таких доменов:
  - **Discord/Telegram Webhooks**: поиск по ним в SIEM/NAD либо полностью отключается, либо выполняется по особым правилам (например, игнорируя сам домен и проверяя конкретный токен бота/канала).
  - **Github и др.**: поиск должен производиться по полному URI (с учётом пути/аккаунта после домена), чтобы выявлять конкретный вредоносный репозиторий, а не весь трафик к GitHub.
